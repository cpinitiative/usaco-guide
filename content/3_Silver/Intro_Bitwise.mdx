## Overview

Below, we'll introduce a couple of concepts necessary for understanding problems with bitwise operators.

### Numbers in Base Two
Whereas we are accustomed to base ten (decimal), in computers, numbers are stored in base two (binary): the only digits are zero and one. Each digit in binary is known as a bit. The rightmost bit is called the least significant bit, while the leftmost bit is referred to as the most significant bit. When we refer to bits, we usually refer to LSBs. The $i$th bit is typically the $i$th LSB, zero-indexed. You may have heard of bytes: a byte is eight bits. Bits form the foundation of computers.

For some problems, you will need to convert numbers between decimal and binary.

To convert from decimal to binary, we find the largest power of two less than or equal to the initial decimal number, subtract that
from our decimal, then repeat until our decimal is zero. We keep track of the exponent associated with the power of two.
At those bits (counting from the right), we set the bit (i.e., make it one). All other bits are zeros, and we can omit
the leading zeros.

Example:
```
d = 5, 2^2 = 4
d = 5 - 4 = 1, 2^0 = 1
```

Now, note the powers of two in this example: `2` and `0`. Thus, the $0$th and $2$nd positions from the right are set to $1$.
This gives us $5$ = $101_2$.

To convert from binary to decimal, the $i$th bit is given a weight $2^{i}$. We add the weight multiplied by the bit to our result.

From the previous example, $101_2 = 1\times2^{2} + 0\times2^{1} + 1\times2^{0} = 5$.

You may be wondering how we can represent negative numbers in binary. Although there are other ways, such as sign and magnitude,
the most common way to do this is by using a technique called two's complement.

In two's complement, the MSB has a weight of $-2^i$ instead of $2^i$. Every other bit is $2^i$. For example, $1101$ will be $-1\times2^{3} + 1\times2^{2}+0\times2^{1}+1\times2^{0} = -3$. This is also the reason a standard C++ `int`'s max is $2^{31} - 1$: a standard C++ `int` has 32 bits, and the MSB is a negative weight while the other 31 bits are positive weights.

In most problems, you just need to be familiar with the unsigned representation, not two's complement.

### Bitwise Operators
Bitwise operators act bit by bit. Most bitwise operators are binary,
meaning they take two inputs: AND `&`, OR `|`, XOR `^`, and shifts.
The only unary bitwise operator (an operator that takes one input)
is NOT `~`.

- AND (`&`) - evaluates whether both bits are `1`. `1 & 1 = 1` but `1 & 0` or `0 & 0` equal `0`.

- OR (`|`) - evaluates whether either bit is `1`. `1 | 1 = 1` and `1 | 0 = 1`, but `0 | 0 = 0`.

- XOR (`^`) - exclusive or, returns `1` when only one bit is `1`. `1 ^ 0 = 1` but `1 ^ 1 = 0`.

- NOT (`~`) - effectively flips the bit: `~1 = 0` and `~0 = 1`.

Bitwise operations are able to be applied to larger strings of bits as well. Binary bitwise operations
compare the strings bit by bit. For example, `1111 & 1010 = 1010`. Unary bitwise operators are applied
bit by bit: `~111 = 000`. More information/examples can be found [here](/CPH.pdf#page=106).

<Warning title="Not">
In actual programming, the bits $111$ aren't just the bits $111$. Instead, there are many leading zeros (depending
on whether your language has integers as $32$ or $64$ bits, or perhaps another representation). Thus, `~111` might
return $1 \dots 11000$.
</Warning>

The truth table below is useful to understand the binary bitwise operators.

### Bitshifts
Using the bitshift operators `>>` and `<<`, we can "shift" our binary representation's
bits to the left or to the right. These are binary operators! The first input is
the binary number to shift, and the second input is how many places to shift that number's
bits by.

A left shift `<<` adds a `0` bit to the LSB. Example:
- `10101 << 1` is `101010`
- `10101 << 2` is `1010100`

A left shift by $i$ is equivalent to multiplying the number by $2^i$.

<Spoiler title="Proof">
Let $x = b_n 2^n + b_{n - 1} 2^{n - 1} + \cdots + b_0 2^0$.

Left shift these bits by $i$ (add $i$ to the power of $2$ they're associated with, then add $i$ zeros to the end):
$$
\begin{align*}
x \ll i= b_{n} 2^{n + i} + b_{n - 1} 2^{n + i - 1} + \cdots + b_0 2^i + 0\cdot 2^{i - 1}+ \cdots + 0\cdot 2^0 \\
x \ll i= 2^i \left(b_n 2^n + b_{n - 1} 2^{n - 1} + \cdots + b_0 2^0\right) \\
\therefore x \ll i = 2^ix
\end{align*}
$$
</Spoiler>

Be careful not to overflow with a left shift! As an example, in C, integers typically only have $32$ bits, so left shifting
too much (like `1 << 32`) may overflow! A left shift by $i$ adds $i$ more bits to the representation (ignoring leading
zeros).

to help with overflow.
</CPPSection>

A right shift is the opposite of a left shift. A right shift by $i$ removes the $0$th through $(i-1)$th LSBs.

There are two kinds of right shifts, determining which digit gets added to be the MSBs.
An arithmetic right shift is used for signed numbers, while a logical right shift
is used for unsigned numbers. Arithmetic right shifts add a copy of the MSB when right shifting, and thus
preserve the sign. Logical right shifts add zero. This is due to how signed binary
integers are typically encoded in two's complement.

However, these little details usually won't be tested on. The key idea to remember is what
happens to the digits that are in the number you're shifting.

A right shift by $i$ is equivalent to the floor of the number divided by $2^i$.
<Spoiler title="Proof">
Let $x = b_n 2^n + b_{n - 1} 2^{n - 1} \dots + b_0 2^0$.

We'll use summation notation because there are some nuances with divisions that are better understood with sums.

Right shift these bits by $i$ (subtract $i$ to the power of $2$ they're associated with). Note that
the $i$ LSBs are now gone!
$$
x \gg i= b_{n} 2^{n - i} + b_{n - 1} 2^{n - i - 1} \dots + b_i 2^0 = \sum_{k=i}^n b_k2^{k - i}
$$
Rewrite the original equation as two terms and factor out $2^i$ from the first term:
$$
\begin{align*}
x = \left(\sum_{k=i}^n b_k2^{k} + \sum_{k=0}^{i-1} b_k 2^{k}\right) \\
x = 2^i\left(\sum_{k=i}^n b_k2^{k - i}\right) + \sum_{k=0}^{i-1} b_k 2^{k} \\
x = 2^i (x \gg i) + \sum_{k=0}^{i-1} b_k 2^{k}
\end{align*}
$$
However, note that $\sum_{k=0}^{i-1} b_k 2^{k}$, when divided by $2^i$, is less than one! Divide $2^i$ on both sides:
$$
\frac{x}{2^i} = (x \gg i) + \frac{\sum_{k=0}^{i-1} b_k 2^{k}}{2^i}
$$
Because the sum term is less than one, we can take the floor on both sides to eliminate that term:
$$
\therefore x \gg i = \left\lfloor\frac{x}{2^i}\right\rfloor
$$
</Spoiler>

### Bitmasks
We can create a bitmask to manipulate/read certain bits from a number. Each digit acts
as a "flag" where $1$ indicates an active flag and $0$ indicates an inactive flag.

Recall how most bitwise operators are binary, meaning they take two inputs.
Our first input to our operator is $n$, while the second input is a bitmask.

Like previous concepts, bitmasks are best explained with examples.

Let's say we want to extract the LSB of a number. Then, we can
have our bitmask be $1$ and use the $\&$ operator.
- If we include some of the leading zeros of $1$, we get $0001$. This means that only the LSB
is active while all other flags are inactive
- Consider a number $1011$. When we do $1011 \& 0001$, the result is $1$, which is the LSB!

### Example: Shifts and Masks
Now, consider this question: how can we extract the $i$-th least significant bit?

<Spoiler title="Hint 1">
How can we extract the LSB of a number $b$?
</Spoiler>
<Spoiler title="Hint 2">
How can we shift something - either the mask or the number - to have the $i$-th LSB bit as the LSB?
</Spoiler>
<Spoiler title="Solution">
Consider our initial mask $1$. This only gets the last bit of a number. We can right shift the number by $i$ to get the $i$th bit
to be the last bit:
$$
(b\gg i)\&1
$$
This helps us extract the $i$th bit from the right by combining bitmasks and bitshifts.

Note that we $\&$ing with a left shift of our bitmask cannot get a bit. While this is able to check if the $i$th LSB is set or not, it is not able to extract it. Instead, it'll either extract $0$ or $2^i$.

For example, $1111 \& 0100$ is $0100$, which is not equivalent to the bit but rather to $2^i$.
</Spoiler>

## Solution - Take a Guess

In fact, we can figure out the sum of two numbers using just their AND, OR and XOR values! Suppose we know their
XOR values, we can use the following property:

$a + b = 2 \cdot (a \& b) + a \oplus b$

The proof is as follows:

$a \oplus b$ is essentially just $a + b$ in base $2$ but we never carry over to the next bit. Recall a bit in $a \oplus b$ is $1$ only if the bit in $a$ is different from the bit in $b$, thus one of them must be a $1$. However, when we add two $1$ bits, we yield a $0$, but we do not carry that $1$ to the next bit. This is where $a \& b$ comes in.

$a \& b$ is just the carry bits themselves, since a bit is $1$ only if it's a $1$ in both $a$ and $b$, which is exactly what we need. We multiply this by $2$ to shift all the bits to the left by one, so every value carries over to the next bit.

To acquire the XOR values of the two numbers, we can use the following:

$a \oplus b = \lnot(a \& b) \& (a | b)$

The proof is as follows:

Recall a bit in $a \oplus b$ is $1$ only if the bit in $a$ is different from the bit in $b$. By negating $a \& b$, the bits that are left on are in the following format:

- If it's $1$ in $a$ and $0$ in $b$
- If it's $0$ in $a$ and $1$ in $b$
- If it's $0$ in $a$ and $0$ in $b$

Now this looks pretty great, but we need to get rid of the third case. By taking the bitwise AND with $a | b$, the ones that are left on is only if there is a $1$ in either $a$ or $b$. Obviously, the third case isn't included in $a | b$ since both bits are off, and we successfully eliminate that case.

Now that we can acquire the sum of any two numbers in two queries, we can easily solve the problem. We can find the values of the first three numbers of the array using a system of equations involving their sum (note $n \geq 3$). Once we have acquired their independent values, we can loop through the rest of the array.

<LanguageSection>
<CPPSection>

```cpp
#include <bits/stdc++.h>
using namespace std;

int ask(string s, int a, int b) {
	cout << s << ' ' << a << ' ' << b << endl;
	int res;
	cin >> res;
	return res;
}

/** @return the sum of the elements at a and b (0-indexed) */
int sum(int a, int b) {
	int and_ = ask("and", ++a, ++b);
	int or_ = ask("or", a, b);

	int xor_ = ~and_ & or_;  // a ^ b = ~(a & b) & (a | b)

	return 2 * and_ + xor_;  // a + b = 2(a & b) + a ^ b
}

int main() {
	int n, k;
	cin >> n >> k;

	// Acquire the first 3 elements
	int a_plus_b = sum(0, 1);
	int a_plus_c = sum(0, 2);
	int b_plus_c = sum(1, 2);

	// Get the actual values by solving the equations
	vector<int> arr{(a_plus_b + a_plus_c - b_plus_c) / 2};
	arr.push_back(a_plus_b - arr[0]);
	arr.push_back(a_plus_c - arr[0]);

	// Get the rest of the array
	for (int i = 3; i < n; i++) { arr.push_back(sum(i - 1, i) - arr.back()); }

	sort(arr.begin(), arr.end());
	cout << "finish " << arr[k - 1] << endl;
}
```

### Solution - Addition

If we perform addition without carrying, then we are simply performing the XOR
(`^`) operator. Then, the bits that we carry over are those equivalent to $1$ in
both numbers: $a\&b$.

<LanguageSection>
<CPPSection>

```cpp
int add(int a, int b) {
	while (b > 0) {
		int carry = a & b;
		a ^= b;
		b = carry << 1;
	}
	return a;
}
```

</CPPSection>

### Solution - Multiplication

For simplicity, we will use the `sum` functions defined above. If we divide up
$b$ into $2^{b_1}+2^{b_2}+\dots+2^{b_n}$, we get the following:

$$
\begin{align*}
&a \times b \\
&= a \times (2^{b_1}+2^{b_2}+\dots+2^{b_n}) \\
&= a2^{b_1}+a2^{b_2}+\dots+a2^{b_n} \\
&= \sum_{\text{bits in b}} {a\texttt{<<}b_i}
\end{align*}
$$

(This same idea is used in binary exponentiation!)

<LanguageSection>

<CPPSection>

```cpp
int prod(int a, int b) {

	while (b > 0) {
		if ((b & 1) == 1) {
			c = add(c, a);  // Use the addition function we coded previously
		}
		a <<= 1;
		b >>= 1;
	}
	return c;
}
```

## XOR Operation

Perhaps one of the most common binary operations in practice is [bitwise xor](https://en.wikipedia.org/wiki/Bitwise_operation#XOR).
The special property that differentiates it from the other bitwise operations is that xor is its own inverse, i.e. $x \oplus x = 0$.

<FocusProblem problem = "sample2" />

### Explanation

Let's analyze the bits of each xor-sum independently. In this case, we'll check for every bit position, i.e.
for every power of two, whether or not it's set in the xor-sum of every contiguous subsequence.
This way, we transformed the problem into counting the number of subsequences with
non-zero xor-sum; this will be applied on the array form by the bits on the same position
in all the values.

### Implementation

**Time Complexity:** $\mathcal{O}(N)$

<LanguageSection>
<CPPSection>

```cpp
#include <iostream>
#include <numeric>
#include <vector>

using namespace std;

int main() {
	int n;
	cin >> n;
	vector<int> v(n);
	for (int &a : v) { cin >> a; }

	long long ans = -accumulate(v.begin(), v.end(), 0LL);

	// For every bit position,
	// check if it's set on in the xor-sum of every subsequence
	for (int i = 0; i < 30; i++) {
		int s = 0;
		// Count the prefix sums
		// The # of 0 xor-sum prefxises starts from 1 to count the prefixes with
		// xor-sum 1
		vector<int> pref = {1, 0};
		for (int a : v) {
			s ^= (a >> i) & 1;
			/*
			 * Count the # of sequences ending at this position with xor-sum
			 * non-zero by counting the prefixes of the inversed bit, i.e.
			 * pref[i] ^ pref[j] = 1. Update the answer by adding the # of such
			 * sequences multiplied by the respective power of two.
			 */
			ans += pref[s ^ 1] * 1LL << i;
			// Update the prexies
			pref[s]++;
		}
	}

	cout << ans << endl;
}
```

## Quiz

<Quiz>
  <Quiz.Question>
    Which of the following will set the kth bit of int x as true? Assume you do not know what the value of the kth bit currently is.
    <Quiz.Answer>
      `x &= (1 << k)`
      <Quiz.Explanation>
        Incorrect. This will set the number to $1<<k$ if the kth bit was true, and 0 if the kth bit was false.
      </Quiz.Explanation>
    </Quiz.Answer>
    <Quiz.Answer correct>
      `x |= (1 << k)`
      <Quiz.Explanation>
        Correct. This will set the kth bit to true regardless of what it currently is.
      </Quiz.Explanation>
    </Quiz.Answer>
    <Quiz.Answer>
      `x += (1 << k)`
      <Quiz.Explanation>
        Incorrect. If the kth bit is already true, it will make the kth bit false and mess up the rest of x.
      </Quiz.Explanation>
    </Quiz.Answer>
  </Quiz.Question>
  <Quiz.Question>
    Which gives the number of subsets for an array of size n? (Include the empty subset)
    <Quiz.Answer>
      `n << 1`
      <Quiz.Explanation>
        Incorrect. This will give n*2.
      </Quiz.Explanation>
    </Quiz.Answer>
    <Quiz.Answer correct>
      `1 << n`
      <Quiz.Explanation>
        Correct. This will give 2^n.
      </Quiz.Explanation>
    </Quiz.Answer>
    <Quiz.Answer>
      `n << 2`
      <Quiz.Explanation>
        Incorrect. This will give n*4.
      </Quiz.Explanation>
    </Quiz.Answer>
    <Quiz.Answer>
      `2 << n`
      <Quiz.Explanation>
        Incorrect. This will give 2^(n+1)
      </Quiz.Explanation>
    </Quiz.Answer>
  </Quiz.Question>
  <Quiz.Question>
    Which checks if the kth bit in int x is true?
    <Quiz.Answer correct>
      `x & ( 1 << k)`
      <Quiz.Explanation>
        Correct. This will check the kth bit in x.
      </Quiz.Explanation>
    </Quiz.Answer>
    <Quiz.Answer>
      `x && (1 << k)`
      <Quiz.Explanation>
        Incorrect. This will be true if x an k are both not 0.
      </Quiz.Explanation>
    </Quiz.Answer>
    <Quiz.Answer>
      `x | (1 << k)`
      <Quiz.Explanation>
        Incorrect. This will be true if either x or k is not 0.
      </Quiz.Explanation>
    </Quiz.Answer>
    <Quiz.Answer>
      `x || (1 << k)`
      <Quiz.Explanation>
        Incorrect. This will be true if either x or k is not 0.
      </Quiz.Explanation>
    </Quiz.Answer>
  </Quiz.Question>
