## Introduction

According to USACO Training section 1.2:

> **Ad hoc** problems are those whose algorithms do not fall into standard
> categories with well-studied solutions. Each ad hoc problem is different; no
> specific or general techniques exist to solve them.

Here are some general tips that may be useful in approaching problems that
appear to be ad hoc.

- Draw lots of small cases to gain a better understanding of the problem. If
  you're having trouble debugging, draw more cases. If you don't know how to
  start with a problem, draw more cases. Whenever you don't know how to further
  approach a problem, you're probably missing an important observation, so draw
  more cases and make observations about properties of the problem.
- Whenever you find an observation that seems useful, write it down! Writing
  down ideas lets you easily come back to them later, and makes sure you don't
  forget about ideas that could potentially be the solution.
- Don't get stuck on any specific idea, unless you see an entire solution.
- Try to approach the problem from a lot of different perspectives. Try to mess
  around with formulas or draw a visual depiction of the problem. One of the
  most helpful things you can do when solving ad hoc problems is to keep trying
  ideas until you make progress. This is something you get better at as you do
  more problems.

In the end, the best way to get better at ad hoc problems (or any type of
problem) is to do a lot of them.

### Explanation

Relabel every cow by its position in $b$, so the target order is $1, 2, \dots, N$ and we must sort $a$ using moves that slide one cow to the left. In the second sample, $a$ becomes $[2, 4, 5, 3, 1]$. The answer is the number of cows that have a larger cow somewhere to their left, which is $N$ minus the number of prefix maxima. Here those are relabeled cows $3$ and $1$, which are original cows $2$ and $4$, exactly the two cows moved in the sample, giving $2$.

Every such cow must move. Suppose $y > x$ and $y$ starts to the left of $x$. Moving any other cow never changes the relative order of $x$ and $y$, and moving $y$ left only takes it further ahead. So the only way to get $y$ behind $x$ is to move $x$. Each modification moves one cow, so we need at least this many modifications.

Moving only those cows is enough. We place cows $1, 2, \dots, N$ at the front in order. Before placing cow $i$, the front holds $1, \dots, i-1$, and every other cow is still in its original relative order, since only placed cows have moved.

- If some larger cow started to the left of $i$, it is still sitting between the front block and $i$. So we slide $i$ left to the end of the front block, which takes one move.
- If no larger cow started to its left, every cow before $i$ was smaller and is already in the front block. So $i$ is directly behind the block and stays where it is.

So cow $i$ moves exactly when a larger cow started to its left, which matches the lower bound.

The code keeps the original labels, so `b[i]` plays the role of cow $i$. `j` scans $a$ and skips cows marked in `moved`, so `a[j]` is always the first cow right after the front block. If `a[j] == b[i]`, the cow is already in place and we advance `j`. Otherwise, a larger cow is blocking it, so we count one move and mark $b_i$ so `j` skips it later. Since `j` only moves forward, the whole algorithm runs in $\mathcal{O}(N)$.

### Implementation

**Time Complexity:** $\mathcal{O}(N)$

<CPPSection>

```cpp
#include <iostream>
#include <vector>

int main() {
	int n;
	std::cin >> n;
	std::vector<int> moved(n);
	std::vector<int> a(n), b(n);

	for (int i = 0; i < n; i++) {
		std::cin >> a[i];
		a[i]--;
	}

	for (int i = 0; i < n; i++) {
		std::cin >> b[i];
		b[i]--;
	}

	int res = 0;
	int j = 0;

	for (int i = 0; i < n; i++) {
		while (j < n && moved[a[j]]) { j++; }

		if (a[j] == b[i]) {
			j++;
		} else {
			res++;
			moved[b[i]] = 1;
		}
	}

	std::cout << res << '\n';
}
```
