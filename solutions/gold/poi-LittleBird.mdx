## Explanation

A DP approach comes to mind naturally. Let $\texttt{dp}_i$ be the minimum number of tiring flights needed to reach tree $i$ from tree $1$.
The initial value is $\texttt{dp}_1 = 0$, and the answer is $\texttt{dp}_n$.
For the transition, tree $i$ can be reached by a flight from any $j \in [i-k, i-1]$, so

$$
\texttt{dp}_i = \min_{j \in [i-k,\, i-1]} (\texttt{dp}_j + [d_j \le d_i]),
$$

where $[d_j \le d_i]$ is $1$ if the bird flies up (or stays at the same height) from $j$ to $i$, which makes the flight tiring, and $0$ otherwise.

However, this transition gives an overall complexity of $\mathcal{O}(QNK)$, which is too slow.
The sliding window technique can be applied here, with a monotonic queue maintaining the candidates for $j$.

To decide which of two candidates $j_1$ and $j_2$ is better, compare their $\texttt{dp}$ values first.
The height only serves as a tie-breaker, because it changes the cost of the next flight by at most $1$,
which can never outweigh a difference in $\texttt{dp}$. Formally, suppose that

$$
\texttt{dp}_{j_1} < \texttt{dp}_{j_2}.
$$

Both values are integers, so ${\texttt{dp}_{j_1} + 1 \le \texttt{dp}_{j_2}}$.
Each flight costs either $0$ or $1$, so regardless of the heights,

$$
\texttt{dp}_{j_1} + [d_{j_1} \le d_i] \le \texttt{dp}_{j_1} + 1 \le \texttt{dp}_{j_2} \le \texttt{dp}_{j_2} + [d_{j_2} \le d_i].
$$

This means $j_1$ is always at least as good as $j_2$, and the heights only matter when the $\texttt{dp}$ values are equal.
This gives a neat way to order the indices in the queue:

- If $\texttt{dp}_{j_1} < \texttt{dp}_{j_2}$, tree $j_1$ is considered better (smaller) than tree $j_2$.
- If $\texttt{dp}_{j_1} = \texttt{dp}_{j_2}$, the tree with the greater height is considered better, since a greater height gives a larger chance of flying down from it.

The best index is at the front of the queue.
There is one more restriction: the length of a flight.
If the index at the front is more than $k$ away from $i$, it is invalid for tree $i$ and for every tree after it, so it is popped from the queue.
Now the front of the queue (let its index be $j$) is safe to use for the update:

$$
\texttt{dp}_i = \texttt{dp}_j + [d_j \le d_i].
$$

To push the new index $i$ into the queue, the trees that are no better than tree $i$
(those with a greater $\texttt{dp}$ value, or an equal $\texttt{dp}$ value and a height not greater than $d_i$)
are removed from the back first, and then $i$ is pushed to the back. This keeps the queue monotonic.

Since each tree is pushed once and popped at most once, a query takes $\mathcal{O}(N)$ queue operations.

## Implementation

**Time Complexity:** $\mathcal{O}(QN)$

<CPPSection>

```cpp
#include <deque>
#include <iostream>

const int MAXN = 1000005;

int d[MAXN], dp[MAXN];

int main() {

	int n, q, k;
	std::cin >> n;
	for (int i = 1; i <= n; i++) { std::cin >> d[i]; }

	std::cin >> q;
	while (q--) {
		std::cin >> k;
		dp[1] = 0;
		std::deque<std::pair<int, int>> candidates;  // {tree index, dp value}
		candidates.push_back({1, 0});

		for (int i = 2; i <= n; i++) {
			// remove trees that are too far back to reach tree i
			while (!candidates.empty() && candidates.front().first < i - k) {
				candidates.pop_front();
			}

			// the front is the best tree to fly from
			dp[i] = candidates.front().second + (d[candidates.front().first] <= d[i]);

			// remove trees with more tiring flights than tree i
			while (!candidates.empty() && candidates.back().second > dp[i]) {
				candidates.pop_back();
			}

			// on a tie, remove trees that are not higher than tree i
			while (!candidates.empty() && candidates.back().second == dp[i] &&
			       d[candidates.back().first] <= d[i]) {
				candidates.pop_back();
			}

			// tree i becomes a candidate for later trees
			candidates.push_back({i, dp[i]});
		}

		std::cout << dp[n] << '\n';
	}
}
```
