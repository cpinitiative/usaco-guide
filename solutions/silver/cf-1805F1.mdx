## Hints

<Spoiler title="Hint 1">

Computing all $\mathcal{O}(N^2)$ pair sums directly is too slow. Try sorting the array and working out a
few sample cases. Do you notice any structure in the indices used in the smallest pairwise sums?

</Spoiler>

<Spoiler title="Hint 2">

For each left endpoint $i$, keep track of the smallest unused pair involving $i$.  Across all $i$, how can we efficiently find the smallest such pair, and update it after using a pair?

</Spoiler>

<Spoiler title="Hint 3">

Applying $F$ directly will eventually overflow, since the smallest value in the array will always double. Additionally, we cannot take the remainder after each application of $F$, since comparisons are necessary.

Try to bound the values in our array after each application of $F$, with a separate scalar to recover the true answer at the end.

</Spoiler>

## Explanation

First sort the array, and fix a left endpoint $i$ of a pair. The sums $a_i + a_{i+1}, a_i + a_{i+2}, a_i + a_{i+3}, \ldots$
are in increasing order, since the array is sorted. So now instead of one big set of $\mathcal{O}(n^2)$ sums,
we have $n - 1$ individually sorted lists, one per left endpoint, and our problem is reduced to finding
the smallest $n - 1$ elements across all of them.

Now, we can maintain a priority queue containing the smallest unused element from each list. Initially,
for every $i$, push $(a_i + a_{i+1}, i, i+1)$ into the queue. We repeatedly pop the smallest sum,
append it to the merged array, and push the next element of that same list, $(a_i + a_{j+1}, i, j+1)$, if it exists.

Since each list is individually sorted, the priority queue will always hold the smallest unused sum
from each list. Thereforce, each extraction is the smallest remaining pair **overall**, so the merged
output will be globally sorted. Each push/pop is $\mathcal{O}(\log n)$ and we do $n - 1$ of them,
so one application of $F$ costs $\mathcal{O}(n \log n)$.


Sadly, we can't repeatedly apply $F$ on the raw values: we need the true relative order of elements to
run the k-way merge correctly, so we can't reduce anything mod $p$ until the very end, but the values
themselves grow enormously over $n - 1$ rounds. In fact, every application of $F$ can nearly double the largest value, so after many rounds
the numbers quickly exceed the range of any integer. This means that we must normalise the array in some way.


We notice that $F$ works nicely with constant shifts: if each element of an array is shifted by $c$,
every pairwise sum shifts by $2c$. So instead of storing the true array directly, maintain it as
$(\text{cur}[i] + \text{offset})$, where $\text{cur}$ is a normalized array used for comparisons and
$\text{offset}$ is a shared scalar. Applying $F$ to the true array is the same as applying it to $\text{cur}$
alone and adding $(2 \cdot \text{offset})$ to the result.
If we stored this new array directly, its values would still continue to grow after every application
of $F$. Thus, we normalize it by subtracting its minimum value. After computing the merged
array $\text{nxt}$, let $m = \text{nxt}[0]$ be its minimum, we update

$$
\text{offset} \leftarrow 2 \cdot \text{offset} + m, \qquad \text{cur}[k] \leftarrow \text{nxt}[k] - m.
$$

Since only $\text{cur}$ is used for comparisons, $\text{offset}$ can be reduced mod $p$ immediately.
Meanwhile, after subtracting the minimum value in each round, $\text{cur}$ always has minimum $0$,
so its entries never overflow.The true final answer is $(\text{offset} + \text{cur}[0]) \bmod p$.


## Implementation

**Time Complexity:** $\mathcal{O}(N^2 \log N)$

<CPPSection>

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MOD = 1e9 + 7;

struct State {
	long long sum;
	int left;
	int right;

	bool operator>(const State &other) const { return sum > other.sum; }
};

int main() {
	ios::sync_with_stdio(false);
	cin.tie(nullptr);

	int n;
	cin >> n;

	vector<long long> cur(n);
	for (auto &x : cur) cin >> x;
	sort(cur.begin(), cur.end());

	long long offset = 0;

	while (cur.size() > 1) {
		int m = cur.size();

		// For each left endpoint, keep its smallest unused pair.
		priority_queue<State, vector<State>, greater<>> pq;

		for (int i = 0; i < m - 1; i++) { pq.push({cur[i] + cur[i + 1], i, i + 1}); }

		// Repeatedly take the smallest available pair and advance its right endpoint.
		vector<long long> nxt;
		while ((int)nxt.size() < m - 1) {
			auto [sum, i, j] = pq.top();
			pq.pop();

			nxt.push_back(sum);

			if (j + 1 < m) { pq.push({cur[i] + cur[j + 1], i, j + 1}); }
		}

		// Fold the common minimum into offset (mod p) to keep cur small
		long long min_sum = nxt[0];
		offset = (2 * offset + min_sum) % MOD;

		for (auto &x : nxt) { x -= min_sum; }

		cur = move(nxt);
	}

	cout << (offset + cur[0]) % MOD << '\n';
}
```
